title: "Releases and source identity"
description: "Choose the right artifacts and keep documentation tied to the code you use."

These guides cover **framework release 0.1.0a4**, published as an experimental
prerelease. Its release page and public provenance asset identify the exact
distribution commit.

| Identifier | What it tells you |
| --- | --- |
| Version/tag | Which named release you intend to install |
| Artifact SHA-256 | Whether downloaded bytes match the published checksum |
| Full distribution commit | Which public Git source State the release identifies |

A checksum is not a Git commit. A branch can move. Keep all three forms of
evidence. Download the wheel, matching source archive, provenance, and
`SHA256SUMS` from the [0.1.0a4 release](https://github.com/peoplebot-framework/peoplebot-releases/releases/tag/v0.1.0a4).

The separately named `syslog-onboarding-v0.1.0` release is a different component,
not a newer framework version. Public documentation can change between package
releases; behavioral claims in these pages are tied to 0.1.0a4. Earlier framework
prereleases remain immutable historical distributions.
